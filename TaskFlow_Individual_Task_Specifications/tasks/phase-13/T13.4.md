**Acceptance criteria met:**
- Duplicate events do not create duplicate effects: `ON CONFLICT (event_id) DO NOTHING` in the outbox insert, and the UNIQUE constraint on `event_id`. Consumer deduplication by `event_id` key documented.
- Retry behaviour bounded: max 5 attempts in the outbox (dead-lettered in-place after 5 failures); `DefaultErrorHandler` retries 3 times with exponential backoff (1s→10s) then forwards to `taskflow.notifications.DLT`.
- Core task API remains usable if notification delivery is delayed: outbox row is written in the same transaction as the task write; relay runs asynchronously via `@Scheduled`; `KafkaTemplate` is `Optional` so the relay bean starts without a broker.
