### Verification

**Artifact created:** `docs/performance-baseline.md`  
**Date:** 2026-10-21

**Summary of findings:**

- Queries are already indexed (V5 migration added `idx_tasks_project_status`, `idx_tasks_project_priority`, `idx_projects_created_at`)
- At current scale (<10 000 rows), DB query time is ~2–3 ms; bottleneck is application/JDBC overhead (~30–60 ms total per request)
- Best caching candidate: per-user project list (`GetProjectsByMemberId` + `CountProjectsByMemberId`), called on every projects page load
- Cache key pattern: `taskflow:projects:user:{userId}:page:{page}:size:{size}` and `taskflow:projects:user:{userId}:count`
- Acceptable TTL: 30 seconds (project membership changes are infrequent)
- Invalidation triggers: project create/delete, member add/remove
- Redis outage must not break the application — requires no-op fallback CacheManager
