**Notable design decisions:**
- The `OWNER` role cannot be set or removed via the membership API — the service throws `IllegalArgumentException` (→ 400) for both attempts, protecting the project ownership invariant until auth is added.
- `authorId` is an explicit request field (pre-auth temporary measure, same pattern as `ownerId` in `CreateProjectRequest`). It will be replaced by `SecurityContext` in the auth phase.
- Comments are scoped to a task (not a project) — `CommentService` validates task existence; cross-project access control is deferred to the auth phase (acceptance criteria explicitly notes "once security is implemented").
- `comments.author_id` uses `ON DELETE RESTRICT` to preserve comment history when a user account is removed; tasks use `ON DELETE SET NULL` for assignees (already established in V1).
