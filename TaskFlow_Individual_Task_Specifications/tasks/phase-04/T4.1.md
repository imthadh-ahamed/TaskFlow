### Requirement
Define the smallest schema that supports users, projects, memberships, and tasks without prematurely modeling every future feature.

**Initial entities:**
- `users`: user identity and account status; password hashes are added only with authentication.
- `projects`: project name, owner, timestamps.
- `project_members`: project/user relationship and membership role.
- `tasks`: project, optional assignee, title, description, status, priority, due date, timestamps.

### Scope
The task scope is defined by the following implementation steps from the source plan:

- Define primary keys, foreign keys, nullability, uniqueness, and status constraints.
- Decide how email normalization and uniqueness are handled.
- Define timestamps and consistent time-zone handling.
- Document deletion behavior for relationships.
- Review whether project ownership is represented by a foreign key and whether owners are also members.
- Avoid adding comments, notifications, audit logs, or outbox tables until their stages.

#### Entities and key constraints reviewed

| Entity | PK | Notable constraints |
|--------|----|---------------------|
| `users` | `bigserial id` | `email UNIQUE CHECK (email = lower(email))`, `is_active boolean DEFAULT true` |
| `projects` | `bigserial id` | `owner_id REFERENCES users RESTRICT`, soft-deleted only via future migration |
| `project_members` | `(project_id, user_id)` composite | `role CHECK IN ('owner','member','viewer')`, `CASCADE` from both parent tables |
| `tasks` | `bigserial id` | `project_id CASCADE`, `assignee_id SET NULL`, `status` and `priority` CHECK constraints |

#### Design decisions documented

- `bigserial` over `uuid` for this phase (evolvable later)
- `text + CHECK` over PostgreSQL ENUMs (simpler migration path to add/remove values)
- Email stored lowercase + DB-level CHECK enforcement
- Owner stored in both `projects.owner_id` (FK) and `project_members` with `role = 'owner'`
- `updated_at` maintained by application layer, not triggers
- `timestamptz` throughout; `due_date` uses `date` (calendar day, not instant)
