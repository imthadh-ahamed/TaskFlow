#### Changes made

**Sort stability (tie-breaker):**

| File | Change |
|---|---|
| `JdbcTaskRepository.findByProjectId` | `ORDER BY created_at DESC` → `ORDER BY created_at DESC, id DESC` |
| `JdbcProjectRepository.findAll` | `ORDER BY created_at DESC` → `ORDER BY created_at DESC, id DESC` |
| `JdbcProjectRepository.findByMemberId` | `ORDER BY p.created_at DESC` → `ORDER BY p.created_at DESC, p.id DESC` |

`id` is a `bigserial` primary key — monotonically increasing and unique — making it a stable, unambiguous tie-breaker. Pages of the same dataset remain in the same order on repeated requests.

**Keyset pagination assessment:** Offset pagination is adequate at this scale. Keyset pagination would improve performance for deep pages (page > 100) but adds complexity and requires cursor management on the client. Revisit if deep-scroll performance becomes a bottleneck.
