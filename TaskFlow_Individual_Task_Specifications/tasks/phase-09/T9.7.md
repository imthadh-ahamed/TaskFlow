#### JWT key rotation procedure

1. Generate a new HMAC-SHA256 secret (≥ 256-bit): `openssl rand -hex 32`
2. Update `JWT_SECRET` in the backend's environment (`.env` / host secrets manager).
3. Restart the backend. All existing sessions immediately become invalid — the old secret is gone.
4. Users will be redirected to `/login` on their next request. They log in again and receive tokens signed with the new key.
5. No database migration is needed; refresh tokens are validated by matching the stored token hash, but their JWT signature is also verified, so old tokens are automatically rejected.

For zero-downtime rotation, deploy a transition period where both old and new secrets are accepted (requires code change to try both keys). This is optional and not currently implemented.
