# Accessibility and UI quality rules

- Use semantic HTML elements and a logical heading hierarchy.
- Provide accessible names for form controls and icon-only buttons.
- Ensure interactive elements are keyboard accessible and have visible focus states.
- Do not communicate status or errors through color alone.
- Associate validation errors with the relevant input when forms are implemented.
- Respect reduced-motion preferences for nonessential animation.
- Use responsive, mobile-first layouts and test common viewport sizes when practical.
- Prefer native controls when they meet the requirement; avoid adding UI libraries without need.
